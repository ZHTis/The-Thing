# hatch-pet 向 work-pets 的能力核对

核对版本：本机官方插件 work-pets 0.1.6，2026-11-26；与本地 hatch-pet 比较。原作者未在本地来源记录中确认，保留原有Apache许可证，不把它标为自建。

| 能力 | 官方已有 | 处理 |
|---|---|---|
| 品牌线索、基础形象、9行动画与16个方向 | 是 | 使用官方 create-pet，无需重复迁移 |
| 分条抽帧、卡片、动图、注册、连续性与盲测 | 是；17个原制作脚本均有对应实现 | 调用已安装官方脚本，不复制官方Proprietary代码到公开库 |
| 共享缩放并保留跳跃高度 | 官方extract_strip_frames改进了自动分组路径 | 保留官方实现，避免旧实现回退 |
| 质量总门槛 | 官方另有validate_pet_quality | 保留官方新增门槛 |
| 失败归因、最小修复、限定预算与改变策略 | 官方入口及shared contract已覆盖 | 沿用官方流程 |
| 隔离盲审的具体任务模板及阶段计时/修复记录 | 官方有原则，旧版有更具体的交接边界 | 提取兼容模板，补充到官方对应阶段，不放行hard failure |
| 24项离线单元回归夹具 | 官方包未附tests目录 | 移入本补充包，适配到官方脚本目录后执行 |
| 旧Codex的row0/column6额外neutral cell | 与官方格式不兼容，官方使用普通idle参考且要求未用槽透明 | 不迁入官方；保留在独立Codex兼容分支，不覆写官方槽位定义 |
| 旧本地pet.json及Codex目录安装 | 与官方Library/Pets MCP生命周期不同 | 不迁入官方；按用户要求保留在独立Codex兼容分支 |
| 旧记录/图像清理策略 | 官方要求保留Library创作与QA产物 | 不移植可能删除官方必留产物的规则 |

本补充包只分发旧hatch-pet的Apache许可测试及本地编写的定位/运行代码，没有复制官方插件的Proprietary源代码。适配后的24项夹具检查官方实现本身，Work分支没有保留第二套制作脚本；Codex兼容实现单独隔离。

原hatch-pet作为可发现技能的入口已移除；完整原件归档在本机备份目录，所需Codex兼容实现与其24项测试迁至compat/codex。共享仓库中的旧提交仍可追溯。官方插件升级后重新运行检查，检查失败先报告差异，不强行用旧算法替换新实现。

另外新增2项官方布局回归，验证标准73个必需槽位通过、旧额外中立帧被拒绝；总计26项。
