# 执行、日志与部分失败

## 引号、编码和错误传播

本机通过subprocess argv启动OpenSSH，远端只拼接受限的powershell/pwsh名称和Base64编码参数；原始脚本保留在日志的command事件中，便于核查 `$_`、中文和路径。编码是传输方式，不是保密或审批绕过方式。

wrapper设置Console输出编码与OutputEncoding为UTF-8，ErrorActionPreference=Stop，并抑制Progress；真正stderr仍与stdout合并记录。部分Windows PowerShell版本可能仍输出CLIXML记录，不要把它们删掉后声称无错。运行器遇到UTF-8替换字符或CLIXML Error记录时拒绝自动验收；其他无法识别的编码或错误记录仍需要另行核验，不以exit=0自动通过。

PowerShell的ErrorActionPreference不会在所有版本自动检查每一次原生程序失败。逐次使用Invoke-CheckedNative；wrapper最后还检查LASTEXITCODE，但这不能替代对中间每个原生调用的检查。用户脚本直接exit也会使完成标记缺失并被视为未验收。

## 日志

JSONL每条包含UTC时间、task_id、run_id、事件类型；命令事件包含目标argv（编码参数以前）、完整可读wrapper和脚本SHA256。SHA256标识执行文本，不证明日志防篡改。output事件是合并stdout/stderr流，不能虚构两个流的精确原始顺序。

每行同时写日志并flush到调用方输出；代理要向用户同步命令和结果，不能只留下无人可见的后台日志。实际凭据不得作为命令参数、正文或上下文。常见token/密码形态会脱敏，私钥块会被抑制；识别不完整，因此首先选择不回显凭据的命令。公开报告只包含必要的脱敏摘录，完整本机日志不进入技能仓库。

中断后运行器会有限排空已收到的尾部输出；`output_capture_complete` 表示本机SSH输出已读到EOF且无读取错误，不表示断连后远端任务日志完整。未排空或读取错误时不能自动验收，保留日志缺口说明。

当前文件内追加写入，写入前按UTF-8字节数轮转：每份最多20,000,000字节，含当前文件共10份；`.1`最新、`.9`最旧，继续轮转时删除最旧份。一个JSON事件不跨文件；单条超限或已有文件超限时明确失败，不截断现有记录。历史归档不可保证覆盖完整任务，需长期留存者先另存。规则由本runner执行，不会给其他脚本或旧写入器自动加上限。

日志不提供加密、防修改或访问审计。新日志以0600创建；已有文件的访问权限由用户本机管理。runner持有独立锁文件上的系统锁，同一路径另一runner写入者在执行前失败；锁文件可保留，锁随进程关闭释放。外部写入器不受该锁约束，因此同一日志不要混用其他写入器。用task/run ID定位。日志写入失败应停止、报告记录缺口，不能把未记录执行伪装成完整审计。

## 失败与恢复

| 事件 | 诚实状态和下一步 |
|---|---|
| 错误密钥/host key不可信/SSH 255 | 连接或认证失败；确认已授权的密钥路径/目标与主机信任，不读私钥、不关闭host key检查 |
| 实际hostname不符 | wrapper在正文前报错；停止修改，先核对目标配置 |
| PowerShell错误或native非零 | 当前步骤失败；保留stderr和返回码，不运行后续步骤 |
| SSH 0但完成标记缺失或输出验收缺失 | failed_or_unverified；查询真实目标状态，不补造成功 |
| 前台超时或中断 | 本机runner终止SSH；远端工作是否仍存活未知，重新只读查询后再决定重试 |
| 一部分完成 | 列出已验收与未开始项；重连核对状态后从适当位置恢复，修改型任务先判断幂等性 |
| 工具超时但SSH子进程可能仍运行 | 报告监控缺口，查本机进程/追加日志和远端状态；超时不是完成信号 |
| 终端自动打开被拒 | 说明没有打开；给出实际日志路径及手动tail命令 |
| 网页授权成功、远端CLI失败 | 认证未确认落地；以远端CLI状态和实际访问为准，优先目标机独立登录 |
| 审批拒绝凭据转发等动作 | 解释被拒动作与理由，停止该动作；不换编码、工具或通道规避 |

runner不会自动重试修改型任务。对于训练和长计算，先明确授权使用工作站已有的持久调度机制，记录任务ID、PID、工作目录、输出日志、状态/退出文件。启动成功仅表示已提交；持续轮询状态及日志，退出后按计划验收输出。未安装调度器时，另行规划，不擅自安装或用隐藏后台进程冒充可靠持久任务。
