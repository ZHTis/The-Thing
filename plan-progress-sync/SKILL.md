# 方案与完成度同步

更新记录时，先确认当前方案，再判定完成度。使用 skill-creator 或 writing-for-agents 修改技能时遵循其指引；本技能只管理记录更新的核验过程。

## 工作流

1. 读取目标记录，核对本对话最新决定及相关方案、代码、配置、产物和运行结果。用户修正优先于旧记录；读取范围限于本次更新需要。
2. 明确当前目标、策略、范围和验收条件。找出变化：新增、替代、取消、降为可选或仍未决定。建议仅被讨论时标为候选，不当成用户已批准方案；先前获授权而未完成的事项继续保留。
3. 依据当前策略重排步骤和依赖。替换过时步骤；取消的步骤从当前执行列表移除，只有理解现行方案需要时才简记变更原因。把实验验证、正式交付及可选延伸分开，避免旧策略残留为强制前置条件。
4. 按更新后的验收条件逐项查证状态：已完成、部分完成、未开始、待决定、当前受阻。已完成须有可定位证据。区分方案已提出、代码已实现、测试已通过、真实数据已运行及效果已验证；文档写了、文件存在或用户讨论过都不自动等于完成。
5. 核对跨记录一致性：人工决定是否已接入代码、配置是否实际启用、产物是否仍来自旧方案。分别记录“结果已保存”和“流程已整合”。发现不一致时标明缺口；仅在本次授权范围内修正，不顺手扩大实现任务。
6. 更新目标记录，保留有效证据和未解决项；保证每个当前步骤有状态，每项重要策略变更反映在步骤里，下一步依赖可满足。无证据的状态使用待核实，不估造完成百分比。历史归档按用户规则保留。
7. 简短报告实际策略变化、完成度变化、下一项工作；没有改变的内容无需重复。明确本次只更新记录还是同时完成了实现。

## 完成检查

- 当前目标和策略匹配最新明确决定。
- 执行步骤、依赖与策略一致，无旧方案的多余门槛。
- 已完成条目有证据，部分完成条目写清剩余部分。
- 新建议、已授权事项、实现与验证分别可辨认。
- 待办、方案和本次修改的文档没有互相矛盾；未修改的旧记录若可能误导，报告其位置。
